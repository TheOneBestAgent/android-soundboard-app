# Story 0.3: Local Desktop Infrastructure Setup - Brownfield Addition

## User Story

As a **developer**,
I want **Electron system tray integration with local file storage and service management**,
So that **the desktop server runs as a background service with user-friendly system tray controls**.

## Story Context

**Existing System Integration:**

- Integrates with: Express.js server and database from Stories 0.1 and 0.2
- Technology: Electron (headless mode), Node.js, system tray APIs
- Follows pattern: Electron main process with system tray integration
- Touch points: Server lifecycle, file system access, system notifications

## Acceptance Criteria

**Functional Requirements:**

1. Electron main process manages Express server lifecycle
2. System tray icon with context menu (start/stop/status)
3. Local file storage management for audio files
4. Service auto-start on system boot (optional)
5. System notifications for server status changes

**Integration Requirements:**

6. Electron IPC communication with Express server
7. File system access for audio file management
8. System tray follows platform conventions (Windows/macOS)

**Quality Requirements:**

9. Graceful server startup and shutdown
10. Error handling for system tray operations
11. File storage operations include proper permissions

## Technical Notes

- **Integration Approach:** Electron main process as service manager with system tray UI
- **Existing Pattern Reference:** Standard Electron application with headless operation
- **Key Constraints:** Must run in background without visible window

## Definition of Done

- [ ] Electron main process starts Express server successfully
- [ ] System tray icon appears with functional context menu
- [ ] Server can be started/stopped via tray menu
- [ ] Local file storage directories are created and accessible
- [ ] Audio file upload/download operations work
- [ ] System notifications show server status
- [ ] Auto-start functionality works (if enabled)
- [ ] Graceful shutdown saves application state
- [ ] File permissions allow read/write access
- [ ] Cross-platform compatibility (Windows/macOS)

## Risk and Compatibility Check

**Minimal Risk Assessment:**

- **Primary Risk:** System permissions or tray integration failures
- **Mitigation:** Fallback to console-based server management
- **Rollback:** Disable Electron wrapper, run server directly

**Compatibility Verification:**

- [ ] System tray works on target platforms
- [ ] File system permissions are properly configured
- [ ] No conflicts with existing system services
- [ ] Auto-start registration works correctly

## IPC Communication Events

```typescript
// Main Process → Renderer Process
interface MainToRendererEvents {
  'server-status': (status: 'starting' | 'running' | 'stopping' | 'stopped') => void;
  'file-uploaded': (filePath: string) => void;
  'error': (error: string) => void;
}

// Renderer Process → Main Process
interface RendererToMainEvents {
  'start-server': () => void;
  'stop-server': () => void;
  'restart-server': () => void;
  'upload-file': (filePath: string) => void;
  'get-server-status': () => void;
}
```
