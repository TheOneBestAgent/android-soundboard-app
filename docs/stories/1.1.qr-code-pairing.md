# Story 1.1: QR Code Pairing

## Status
Draft

## Story
**As a** content creator using multiple devices,
**I want** to pair my mobile soundboard app with my desktop streaming setup via QR code,
**so that** I can control audio playback remotely during live streams with secure, low-latency connectivity.

## Acceptance Criteria
1. QR code generation on desktop/web interface displays pairing code
2. Mobile app can scan QR code using device camera
3. Pairing establishes secure WebSocket connection with mTLS
4. Connection status is clearly indicated on both devices
5. Pairing succeeds within 10 seconds of QR code scan
6. Failed pairing attempts show clear error messages
7. Multiple mobile devices can pair with single desktop instance
8. Pairing persists across app restarts until explicitly disconnected

### Security Requirements
[Source: architecture/security-and-performance.md]
- TLS 1.3 encryption for all WebSocket connections
- Certificate pinning for mobile app connections
- JWT tokens with 5-minute expiration for pairing sessions
- mTLS authentication for device verification
- Rate limiting on pairing endpoints (max 5 attempts per minute)

### Performance Constraints
[Source: architecture/security-and-performance.md]
- QR code generation: <500ms
- Pairing connection establishment: <10 seconds
- WebSocket message latency: <50ms
- Connection status updates: Real-time (<100ms)

### Technical Dependencies
[Source: architecture/tech-stack-definition.md]

- **QR Code Scanning**: react-native-qrcode-scanner
- **WebSocket**: Socket.io 4.7+ with TLS support
